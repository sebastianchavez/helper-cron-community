# HelperCron Community

**HelperCron Community** は、**Angular 19** と **Electron** で構築された無料のデスクトップアプリケーションです。再利用可能なブロックによる視覚的なノーコードフロー自動化ビルダー、Ollama によるローカルAIチャット、cronライクなスケジューラー、実行ログ、フローカレンダーを組み合わせており、クラウドへの強制的な依存なしにすべてローカルで動作します。

## 機能

- **ビジュアルフロービルダー** — 再利用可能なブロックで自動化ワークフローを構築するノーコードキャンバス
- **Cronスケジューラー** — フローを固定間隔または選択した曜日の特定の時刻に実行するようスケジュール設定；完全にバックグラウンドで動作
- **AIチャット** — Ollamaを使ってローカルでリアルタイムストリーミング応答付きでチャット
- **会話管理** — 会話の作成、名前変更、削除；名前付きフォルダーで整理
- **実行ログ** — ステップバイステップの詳細ログ、実行時間、ステータスを含むフローごとの実行履歴
- **カスタムログストレージ** — フローはSQLiteに名前付きキーバリューログを書き込み、後で照会または削除可能
- **フローカレンダー** — スケジュールされたフローと過去の実行を可視化する日/月/年カレンダー
- **ダーク/ライト/システムテーマ** — 5つのアクセントカラープリセットを持つ3つのテーマモード
- **7つのUI言語** — スペイン語、英語、ドイツ語、フランス語、ポルトガル語、日本語、中国語

## はじめに

### 前提条件

- **Node.js** ≥ 18
- **Ollama** *（オプション）* — ローカルAIモデルを使用するには [ollama.com](https://ollama.com) からインストール

### 依存関係のインストール

```bash
npm install
```

> `postinstall` はインストールされたElectronバージョンに合わせてネイティブモジュール（`better-sqlite3`）を自動的に再ビルドします。

### 開発環境での実行

```bash
npm run electron:dev
```

3つのプロセスを同時に起動します：

1. `ng serve` — `http://localhost:4200` でAngular開発サーバー
2. `tsc --watch` — Electronメインプロセス用TypeScriptコンパイラー
3. `electron` — 開発サーバーの準備ができたら `http://localhost:4200` を読み込む

## アプリケーションページ

### ダッシュボード

起動後のエントリポイント：

- **統計カード** — フロー総数、アクティブ（スケジュール済み）フロー、会話総数、利用可能なAIモデル
- **最近の実行** — ステータス付きの最後のフロー実行（成功 / エラー）
- **クイックアクション** — タスクビルダー、チャット、カレンダー、AIモデルへのショートカット

### タスクビルダー（フロー自動化）

コア機能。フローを構築する**ビジュアルキャンバス**：

1. 左サイドバーからキャンバスにブロックタイプをドラッグ
2. 出力コネクタから入力コネクタにドラッグしてブロックを接続
3. 右パネルで各ブロックを設定（クリックして選択）
4. **スケジュール**を設定（間隔または特定の時刻 + 曜日）
5. 手動実行するには**実行**をクリック、またはスケジューラーが処理するために保存

キャンバス機能：パン（中クリックドラッグ）、ズーム（スクロールホイール）、複数選択（Shift+クリック）、右クリックコンテキストメニュー、すべてのテキストフィールドでの `{{varName}}` 補間。

### フローライブラリ

保存されたすべてのフローの参照と管理：

- グリッドまたはリストビュー、名前で検索、並べ替えオプション
- スケジュール済みフローのみにフィルター
- フローの名前変更、複製、削除、有効化/無効化
- ライブラリから直接フローをクイック実行

### フローカレンダー

スケジュールされたフローと実行履歴の可視化：

- **日ビュー** — 1日の実行を示す時間単位グリッド
- **月ビュー** — 日ごとの実行ドット付き月次グリッド
- **年ビュー** — 年間アクティビティヒートマップ

任意の実行をクリックすると、ステップバイステップの詳細ログが開きます。

### AIチャット（Chatbot）

Ollamaとのフル機能チャット：

- Ollamaローカルモデルセレクター
- トークンごとのストリーミング応答
- 会話管理（作成、名前変更、削除）
- 名前付きフォルダーでの会話整理
- 最初のやり取りの後に自動生成される会話タイトル

### AIモデル

利用可能なOllamaモデルの表示と管理：

- ローカルで利用可能なすべてのOllamaモデルを一覧表示
- Ollamaサービスステータスの確認
- APIキー不要 — Ollamaは `http://localhost:11434` で自動検出

### カスタムログ

**Save Log**ブロック経由でフローが書き込んだログエントリの検索可能なページ付きテーブル：

- ログ名、フロー、日付範囲でフィルター
- 生/テーブルJSONビューアーを持つ詳細モーダル
- 個別エントリの削除またはフィルターによる一括削除

### 設定

- **言語** — 7つの言語を切り替え（即時反映）
- **テーマ** — ライト、ダーク、またはシステム（OS設定に従う）
- **アクセントカラー** — ブルー、グリーン、ピンク、アンバー、またはバイオレット
- **Ollama** — サービスステータスの確認、ローカルデーモンの起動/停止

## ブロックタイプリファレンス

| ブロック | カテゴリ | 説明 |
|---|---|---|
| `api-rest` | インテグレーション | HTTPリクエスト（GET/POST/PUT/DELETE/PATCH）。レスポンスステータスに基づいて `2xx`、`4xx`、`5xx` の出力ポートにルーティング。ヘッダー、ボディ、`outputVar`、データマッピングをサポート。 |
| `ai-prompt` | AI | 選択したOllamaモデルにプロンプトを送信；テキスト応答を `outputVar` に格納。 |
| `local-storage` | データ | 永続ローカルストレージで名前付きキーを読み書き。 |
| `set-variable` | 変数 | リテラル値または式を名前付きフロー変数に割り当て。 |
| `save-log` | ロギング | カスタムログテーブルに名前付きログエントリ（キー + 値）を書き込み。 |
| `delete-log` | ロギング | 名前フィルターに一致するログエントリを削除（オプションで現在のフローに限定）。 |
| `fork` | 制御 | 実行を複数の並列ブランチに分割（ファンアウト）。 |
| `join` | 制御 | すべての受信ブランチが完了するまで待機してから続行（ファンイン）。 |

### 変数補間

すべてのテキストフィールドは `{{varName}}` 構文をサポート。変数は現在のフローコンテキストから実行時に解決されます。

### データマッピング

オブジェクト結果を生成するブロック（`api-rest`、`ai-prompt`）は**データマッピング**をサポート：結果からネストされたプロパティを抽出し、後続ブロック用の名前付き変数に格納。

## フロースケジューラー

**Electronメインプロセス**で実行され、**30秒ごと**に有効なフローのスケジュールを確認します。

スケジュールタイプ：

- **間隔** — 最後の実行からN分 / 時間 / 日ごと
- **特定時刻** — 選択した曜日（月〜日）の設定されたHH:MMに

各実行：

1. 接続されたすべてのブロックを通じてフローを順次実行
2. ステップバイステップの完全な実行ログをSQLiteに永続化
3. 結果を含むOSデスクトップ通知を表示

同じフローの同時実行は防止されます。

## データストレージ

すべての永続データは単一の**SQLite**データベースに保存されます：

```
%APPDATA%\HelperCron\chat.db                        (Windows)
~/Library/Application Support/HelperCron/chat.db    (macOS)
~/.config/HelperCron/chat.db                        (Linux)
```

| テーブル | 内容 |
|---|---|
| `conversation` | タイトルとフォルダー付きチャット会話 |
| `message` | 個別チャットメッセージ（ロール、コンテンツ、タイムスタンプ） |
| `folder` | 会話フォルダー |
| `flow` | 保存された自動化フロー（キャンバスJSON、スケジュール設定） |
| `execution_log` | ステップログと実行時間を含むフローごとの実行履歴 |
| `custom_log` | フローが書き込んだ名前付きキーバリューログエントリ |
| `user_profile` | ユーザー表示名 |

WALモードは書き込みパフォーマンスとクラッシュ安全性のために有効化されています。スキーママイグレーションは起動時に自動実行されます。

## セキュリティ

- **コンテキスト分離** — `contextIsolation: true`、`nodeIntegration: false`；rendererは `preload.ts` の `window.agi` ブリッジ経由のみでメインプロセスと通信
- **パストラバーサル保護** — `resolveSafePath()` がすべてのファイルシステム操作を設定されたプロジェクトルートに検証・制限
- **コマンドホワイトリスト** — ターミナル実行を `node`、`npm`、`npx ng` に制限；任意のコマンドは拒否
- **ネットワーク非公開** — アプリケーションはサーバーポートを開かない；すべてのIPCはローカル

## 国際化

言語ファイルはフラットなJSONキーバリューマップです：

```
src/assets/i18n/
  es.json   (スペイン語 — デフォルト)
  en.json   (英語)
  de.json   (ドイツ語)
  fr.json   (フランス語)
  pt.json   (ポルトガル語)
  ja.json   (日本語)
  zh.json   (中国語)
```

アクティブな言語は `localStorage` に保存され、リロードなしに実行時に変更されます。
